# 决策记录

> 只记录需要长期回看的架构、接口、依赖或流程取舍。

### 2026-08-31 — 采用按需维护的协作文档层

- 背景：需要把通用项目模板的有效协作规则带入一个已有的 Obsidian 插件。
- 决策：保留交接、项目记忆、变更日志和三个专题文档；不复制模板关系图、自检脚本或空白模板内容。
- 备选与取舍：直接覆盖现有 `AGENTS.md`/`README.md` 会丢失插件专项约束和用户文档，因此只新增缺失文档并按真实项目填充。
- 影响：后续会话有稳定的接力和验证入口，模板专属内容不会进入发布包。
- 何时重新评估：项目不再需要长期文档维护，或形成更适合插件的文档结构时。

### 2026-11-17 — 图片转换作为独立页签，不计入 9 类体检

- 背景：图片转换会真实改写文件与引用，风险和耗时都高于只读扫描；若纳入体检分类，会扭曲首页健康度与“扫描只读”的承诺。
- 决策：图片转换放在标签条末尾的独立页签，不进入 `CLEANUP_CATEGORIES`；估算按当前选项真实重编码，执行按单张事务串行并支持中止。
- 备选与取舍：合并进“未引用图片”分类可以让入口更少，但会让扫描与改写混在一起，也无法单独预估节省空间，故不采用。
- 影响：首页数量、健康度与 6 阶段扫描都不包含转换候选；转换状态的估算结果只保存在内存中，不写入体检缓存。

### 2026-11-17 — 体检缓存只落纯数据

- 背景：把带 `TFile`/`TFolder` 的候选对象直接写入 `data.json` 会触发循环引用，且旧缓存字段缺失时容易让面板崩溃。
- 决策：`src/cleanup/cleanup-cache.ts` 采用 v2 格式，只保存路径与 `size`/`mtime`，读取时按路径重新解析；逐项校验，无法解析的条目直接丢弃；保存失败只提示一次。
- 影响：缓存可以跨重命名或删除安全恢复；新增候选类型时必须同步更新序列化与恢复逻辑。

### 2026-11-17 — 关联笔记移动使用原生文件管理器并支持撤销

- 背景：批量移动需要遵循用户自己的链接更新设置，同时要能纠正误操作。
- 决策：移动通过 `app.fileManager.renameFile` 执行，目标已存在的文件跳过、不覆盖；面板保留最近一次移动的记录，提供“撤销本次移动”按相反顺序移回。
- 影响：撤销只对最近一次移动生效；原路径被占用、文件已改名或删除时跳过并逐项报告。

### 2026-11-17 — 发布同时提供 ZIP 与三件套

- 背景：Obsidian 社区目录只识别 `main.js`、`manifest.json` 与可选的 `styles.css`，手动安装则需要更省事的下载方式。
- 决策：Releases 同时附三件套与根层打包的 `vault-doctor-<版本号>.zip`；ZIP 由 `scripts/package-plugin.mjs` 生成，不自动构建，包内版本必须与 `manifest.json` 一致。
- 影响：ZIP 不是安装器；发布前必须执行 `npm run package` 并校验包内版本、条目与 SHA-256。
