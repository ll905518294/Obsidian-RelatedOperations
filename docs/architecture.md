# ARCHITECTURE

> 描述插件的模块边界、数据流和稳定约束；实现变化后以代码行为为准同步更新。

## 1. 项目目标
- 解决：在 Obsidian Vault 中发现关联笔记、断链、未引用资源和重复文件，并提供可确认的整理/清理操作。
- 用户：需要维护笔记关系和 Vault 健康状况的 Obsidian 用户。
- 不解决：不覆盖目标文件，不在无确认的情况下删除重复文件，不把外部云服务作为运行前提。

## 2. 系统概览
- 核心模块：
  - `src/main.ts`：插件生命周期、命令、Ribbon、菜单和视图注册。
  - `src/related-notes*.ts`：关联笔记计算、桌面视图和移动端 Modal。
  - `src/orphan-cleanup*.ts`：Vault 体检与清理流程、桌面视图和移动端 Modal。
  - `src/broken-*-links.ts`、`src/native-image-links.ts`：链接扫描与转换。
  - `src/cleanup-*.ts`、`src/duplicate-files.ts`：候选筛选、风险分级、报告和重复文件扫描。
  - `src/link-stats*.ts`：关联数量属性维护。
  - `src/settings.ts`、`src/core-utils.ts`：设置与共享规则。
- 外部依赖：Obsidian API；可选集成 Notebook Navigator。

## 3. 关键数据流
1. Obsidian 命令、Ribbon 或菜单触发入口。
2. 插件从 Vault/metadata cache 收集 Markdown、Canvas 和资源信息。
3. 扫描模块生成可操作候选，视图展示并要求用户确认。
4. 执行阶段使用 Obsidian 文件 API 或编辑历史；报告可复制或写入 Vault 根目录。

## 4. 关键约束
- 只对已解析或可安全判定的目标执行操作；外部 URL、代码块和 frontmatter 按功能规则保守处理。
- 不覆盖已有目标文件；失败项与已完成项分别报告。
- 监听器、定时器和视图必须通过 Obsidian 注册机制清理。
- 移动端避免依赖桌面 Electron API，桌面功能提供 Modal fallback。

## 5. 当前边界
- 体检首页标签数量与首页候选总数一致（重复文件按文件组计数）；扫描结束后有候选的分类靠左，同组保留原顺序。初次渲染和增量更新使用同一套数量及排序规则，移动现有按钮而不重建列表。
- 切换待复核分类先渲染已有结果，再异步扫描当前分类；同类切换与手动刷新共用一个在途任务，完成后只刷新当前分类或首页，否则仅更新标签计数。复核中及复核失败保留脏标记时，处理按钮禁用。
- 首页以单个概览区展示扫描状态、候选总数及待复核分类数；结果按优先处理、已检查、待检查/复核分组。分类卡片的操作在正文下方，缓存或变化导致的过期结果不视为已确认无问题。
- 全量体检在首页显示按阶段计算的进度和模块状态，扫描器在分类完成时发布对应候选；完整结束前禁用分类切换和处理入口。扫描失败保留已完成分类结果，未完成分类保留待刷新状态。
- 关联数量自动更新对比已解析链接缓存，仅检查修改过的笔记和变化链接两端；启动、启用或手动命令保留全量初始化。缓存对比仍遍历内存中的链接图，不做全库属性读写。
- 体检面板随 metadata cache 更新单个源笔记的链接候选和位置；移除/转换链接后不再完整体检，清理文件后移除已删除候选并更新空文件夹。当前分类的“刷新”每次都会重算该分类；首页以分类卡片提供单类扫描，并保留“全部扫描”作为显式全量入口，单类扫描期间阻止全量并发。
- 内容修改标记资源、空文件与重复文件分类为待刷新；文件创建、删除和重命名也标记链接与文件夹分类。进入待刷新分类时只重算该分类，失败后保留标记以便重试。删除前保留保守的引用与空文件条件复核；重复文件删除前先移除 Markdown 中指向目标的文件链接，链接清理失败则跳过删除。
- 扫描期间的变更事件只记录脏状态，不触发并发 UI 刷新；扫描完成后仍会保留待刷新标记。分类扫描按分类版本确认结果，扫描期间的新事件不会被旧结果确认。
- 分类扫描只在成功完成后更新对应候选；失败时保留已有结果并保留待刷新标记，不回滚整个候选集合。
- 体检面板从设置缓存恢复时，所有分类先标记为待刷新；首页卡片显示“内容已变化”，进入分类后按需重新计算。
- Notebook Navigator 为可选插件，未安装时核心功能仍应可用。
- 部署脚本依赖当前打开的唯一 Vault 和本机 Obsidian CLI。
